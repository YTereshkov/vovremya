# PWA и offline schedule

Vovremya остаётся одним responsive React SPA. `manifest.webmanifest` задаёт standalone PWA, а Service Worker хранит только shell, иконки и статические frontend assets. Запросы `/api/*`, `/health` и все mutating requests Service Worker не перехватывает и не кэширует. В production необходим HTTPS; localhost допустим для локальной разработки.

После входа frontend синхронизирует календарь в пределах 7 прошедших дней, сегодня и 30 дней вперёд относительно локальной даты в timezone организации. Из-за ограничения `/api/calendar` на 31 день диапазон читается двумя запросами. Список специалистов читается отдельно. Проверяются возвращённые даты/timezone и текущий серверный AdministratorAccount перед записью. Повторная синхронизация происходит раз в 5 минут при подключении и после invalidation календарных query при изменениях расписания.

Последний успешно проверенный снимок хранится в IndexedDB вместе с идентификаторами AdministratorAccount и Organization, timezone, диапазоном и временем синхронизации. Хранилище содержит только один текущий account: смена аккаунта удаляет прежний снимок; успешный logout или серверный 401 очищают его. Офлайн-чтение требует совпадения сохранённых account/tenant идентификаторов. Пока сеть недоступна, серверная сессия не может быть повторно проверена; локальная копия не является новой авторизацией на сервере. Устройство и браузерный профиль должны быть защищены, поскольку снимок содержит данные клиентов и не шифруется приложением.

В offline режиме разрешены только `/` («Сегодня») и `/calendar`, и только просмотр дат сохранённого диапазона. Создание, редактирование, отмена, перенос, результаты, сообщения и остальные mutation routes заблокированы. API mutations дополнительно отклоняются до отправки fetch; сервер остаётся окончательным источником бизнес-правил. В UI видны время последней синхронизации, сохранённый диапазон и предупреждение «Только просмотр». Если данных на дату нет в сохранённом диапазоне, UI не подменяет это обычным пустым расписанием.

После восстановления соединения frontend заново проверяет `/api/me`, загружает актуальные календарные данные с сервера и обновляет снимок. Если офлайн-дата изменилась и снимок уже не покрывает ожидаемые 7+30 дней, показывается его фактический диапазон, а не обещание нового горизонта.

Если запрос API потерял сеть при `navigator.onLine === true`, скрытый `/health` probe продолжает попытки с интервалом 5 секунд даже в offline режиме. Успешный ответ восстанавливает online состояние без обязательного браузерного `online`-события; HTTP-ошибка отдельного endpoint не превращается сама по себе в offline.
